# All-variant source and layout audit

2026-10-17, rechecked after the Dancer omissions. Scope: all four Accord variants on all 21 supported combat jobs, plus the 11 noncombat pages and inherited base classes. This supersedes the broad completion claims in the earlier implemented-intents document. It includes the preceding [protection correction](protection-routing.md), with the Scholar targeting correction below. Implemented locally; not published or validated in game.

## Rules applied

A button expresses a distinct request. A manual burst or class-mechanic initiation must continue through the appropriate damage rotation without repeated visits to a buff selector. Automatic initiation removes a duplicate control unless the same action also provides a distinct function such as placement, preparation without a target, chosen-recipient aid, emergency recovery, movement or resource conversion. Healing buttons remain healing intents; Support does not gate all healing. A category can have no extra effect for a job.

Only successful actions activate burst continuation. Existing readiness, status, resource, target, range, HP and content checks still govern follow-through. The audit does not redefine resource reserves or promise immediate execution irrespective of those checks.

## Changes from this broader pass

- Auto burst now removes the added Presence of Mind, Chain Stratagem, Divination and Devilment initiators, and Machinist's Heat Blast burst selector. Their damage-route follow-ups remain enabled.
- Dark Knight gets a dedicated Interject control in both modes. Interrupt is removed from the burst selector, which disappears in Auto burst. Delirium/Living Shadow continue through the existing bounded handoff.
- Ninja's TCJ control now starts TCJ rather than substituting Meisui for an unrelated Shadow Walker status. Its advanced damage paths already complete TCJ; the existing TCJ-result feature enables subsequent Meisui. Direct Meisui is separately available for deliberate resource conversion. Hide and Kassatsu keep prepull functions.
- Auto class mechanics removes Bard's duplicate song initiator, AST's draw initiator and Dancer's Technical Step control. Dancer now also removes Standard Step in A. The added targetless noncombat initiation was removed on 2026-10-17: it exceeded the requested intent routing. Upstream initiation conditions remain. Accepted steps/finishes remain independent of automatic initiation.
- Monk's Mantra now belongs to Support. Manual Support exposes Mantra directly; automatic Support uses the existing ST eligibility on both damage paths through a new optional AoE feature.
- Bard's Nature's Minne button disappears in automatic Support. Paean remains for chosen-recipient cleansing and anticipatory debuff prevention; its automatic route only responds to an existing cleansable effect.
- Dancer's partner presets now belong to Support. A new optional AoE feature supplies the same in-combat partner policy as ST, after dance completion checks. Closed Position/Ending is now present only in manual Support, with the recommendation selector disabled so it honours the selected ally. In automatic Support, existing partner rules handle selection; a duplicate manual button is not required.
- Machinist gets an optional automatic AoE Wildfire route using existing ST eligibility and HP/content settings. Previously the added AoE route required an active burst handoff; without a recent Barrel/Wildfire confirmation, routine AoE Hypercharge could not offer Wildfire. Manual follow-through retains its previous conditions.
- Scholar's shield-preparation control now enables Adloquium and Deployment retargeting together with their parent. This keeps eligibility, shield application and spreading on the same resolved ally. The preceding protection pass had added the selector without these settings.
- All imported empty variant slots now identify their retired action, as the new protection blanks already did. Live/setup can clear a known obsolete control with cleanup off, while preserving unrelated assignments. Static variant changes still do not write hotbars.

Additional findings from the 2026-10-17 recheck:

- Dancer already has ST/AoE Improvisation presets (4022/4049). Accord now enables them with Support. ST retains its nearby-allies and Technical Finish exclusions; AoE retains its existing combat/dance exclusions. A separate default-off finish capability checks the game's native Improvisation replacement before the damage path chooses anything else. The next damage press uses Improvised Finish; waiting between presses allows a longer channel. It remains enabled for Accord in manual Support too, so changing mode after initiation cannot strand the finish. Protection interception yields to this continuation. This does not add a channel timer or automate movement.
- Machinist already has AoE Flamethrower preset 8305, including stationary-time, HP, overheat and Reassemble checks. Mechanics now delegates this initiation; the separate button exists only in M. Its native AoE channel hold is reused, and an optional interception guard prevents injected protection from cancelling it. ST remains damage intent, not a second Flamethrower initiator. Moving or explicitly choosing another action still cancels the channel.
- Samurai already has ST Third Eye/Tengentsu preset 15094. Protection now enables it and an optional AoE route reuses `UseThirdEye` (incoming damage, or solo). Its separate button is removed in A. Tengentsu's benefit follows the game's status/hit handling; there is no additional finisher button to preserve.
- Monk already has ST Riddle of Earth preset 9096. Protection now enables it and an optional AoE route uses the same incoming-damage check. Support separately enables available Earth's Reply on both damage paths with the existing party-health and range conditions, including after manual Riddle initiation. The Riddle button remains because its native Earth's Reply replacement gives direct party healing above the automatic threshold. This is a healing function, not a claim that Wrath cannot automate Riddle.

All additions default off in an unconfigured fork and are restricted to the relevant jobs. Accord sets the capabilities through the settings API. Existing numeric thresholds, movement settings, recipient priorities and reserve settings are not rewritten when a variant changes.

## Source evidence

The review uses the current local Wrath 1.0.4.27 fork, not historical prose as proof. For each job the enabled presets were reconciled against `Accord.Plugin/presets.json`, `SetupPack.Resolve`, controlled membership, optional feature scopes, and the source branches below. Source paths here are relative to the repository root.

- `WrathCombo/Engine/IntentRouting.cs`, `BurstPolicy.cs`, `IntentHandoff.cs`: successful-action confirmation, bounded continuation, preset overrides, TCJ-result distinction and reset behaviour. Existing tests cover failed/expired inputs, reverse-order handoff, no timer extension and category exclusions.

## Validation and limits

Final local validation passed **12,144 assertions across 512 job/variant combinations**, including the independently named continuation prerequisites. Both plugin builds succeeded. The fork reported its 72 existing warnings; Accord reported none. Tests cover all 512 job/variant combinations, explicit initiator presence/absence, all 21 jobs' retained distinct utility, category ownership, manual restoration, no baseline mutation, and preset-only updates. Actual engine-schema validation checks that every referenced setting/preset exists and round-trips. New features remain disabled in upstream-default configurations. Existing handoff and Bridge transaction tests still apply.

This is a source/configuration/layout review, not evidence of native gameplay timing. In-game acceptance still needs the updated plugins: selected-class setup/live transitions, target resolution, and actual sequence execution cannot be proven by compilation. The MCH AoE finding is a specific source gap, not a diagnosis of the earlier level-90 solo trial clear-time comparison.


## Recheck method and access decisions (2026-10-17)

The earlier eight-button Dancer answer was not adequately supported. In particular, neither "channelled" nor "can be pressed deliberately" establishes a separate intent. The recheck followed the actual configured advanced ST/AoE branches, their helper predicates, the standalone selector (where retained), and the effective A/M preset membership. `tests/ActionAccess.cs` now independently names the engine presets required for accepted sequences and retained controls for all 21 jobs; the built-engine test resolves those names and checks them in every combination. It also checks Ninja's two TCJ-completion booleans and Bard's two party-cleanse booleans. These are configuration regression checks, not a simulation of the native action manager.

### Dancer access after correction

With all variants enabled the job page has **five occupied controls**: Cascade, Windmill, En Avant, Curing Waltz and Peloton. Standard/Technical return in manual Mechanics; Closed Position/Improvisation return in manual Support; Devilment returns in manual Burst; Samba returns in manual Protection. Static settings changes still require explicit hotbar setup; live mode applies the layout. Empty slots carry their retired action identity so known duplicate buttons can be removed even with general cleanup disabled.

The earlier targetless-start addition was an unjustified expansion and has been removed. The pinned upstream ST prepull start requires a battle target; the generic ST/AoE start requires target HP above a threshold. Both already complete accepted dances targetlessly. Preserve those initiation rules and the existing `FinishOrHold` behaviour. Auto mechanics is not permission to repeatedly prepare while idle.

Validation limits: the test harness loads the compiled engine schema and verifies configuration round-trips and prerequisite membership. The new native-action branches have been source-reviewed and compiled, not exercised inside FFXIV. Nothing has been installed, committed or published by this correction.
