# Testing channel preparation

The `testing` branches retain `Accord`, `WrathCombo`, and `RotationSolver` identities. Stable source branches and published feeds are unchanged.

All three source repositories have a `Build testing candidate` workflow. Pushes to `testing` run validation. Manual dispatch with a four-part `testing_version` builds that exact DLL version and uploads a candidate artifact after packaging checks; it does not publish. An explicit `testing-vA.B.C.D` tag triggers the complete build/package checks and immutable prerelease publication. The tagged source must belong to the testing branch. The publisher is pinned to reviewed central commit `3c2396b29baf30d751ceb273708d8bfb64ee019a`; publish that central source before consuming runs. GitHub manual dispatch availability may require registering the workflow on the default branch; testing branch pushes and explicit tag pushes do not depend on that manual interface.

The packaging entry points are `tools/package_testing.py --tag testing-vA.B.C.D --stable-feed <current-stable-feed.json>` and `tools/check_testing_package.py` with the same arguments. The candidate goes under `artifacts/testing`. Its immutable tag prefix does not match stable `v*` release triggers. The source repository's `pluginmaster.json` is never written by testing packaging.

The resulting candidate feed retains every stable entry and its `AssemblyVersion`, install URL, update URL and other metadata. Only the matching entry's `TestingAssemblyVersion`, `TestingDalamudApiLevel` and `DownloadLinkTesting` are overlaid. A stable version that catches or exceeds the candidate supersedes it. Tests cover stable preservation, unchanged identities, version validation and separation of stable/testing tags and output paths.

Do not publish this snapshot as a frozen alternative stable feed. The central testing branch now contains a composer that refreshes stable inputs on every sync and applies verified immutable candidate pointers afterward. It writes only `testing-pluginmaster.json`. Register a published candidate's `testing-release.json` in `testing-sources.json`; the composer checks the ZIP manifest/checksum before advertising it. A newer stable release supersedes an older test. Promote the prepared central refresh workflow to the central default branch to activate its hourly schedule before advertising a maintained install feed. The source stable workflows/feeds remain independent.

Draft publication is recoverable; published retries must have identical assets and never overwrite a release. The publisher does not publish the frozen combined feed, update root `pluginmaster.json`, or change the stable latest-release marker. RSR's inherited broad tag publisher excludes testing tags.

On 5 November the source and flows were published to `testing` in `kaldigo/FFXIVAccord`, `kaldigo/WrathCombo`, `kaldigo/RotationSolverReborn` and `kaldigo/DalamudPlugins`. The central push-triggered composer succeeded and created its testing-only feed. Candidate registrations are still empty, so that file does not yet advertise the local experimental packages. Its hourly schedule still requires default-branch workflow registration before it can be advertised as a maintained installation feed.

Local candidate versions checked against the current stable feeds are Accord `0.2.15.15`, Wrath `1.0.4.38` and RSR `7.5.7.16`; stable was respectively `0.2.15.14`, `1.0.4.37` and `7.5.7.15`. ZIPs, checksums and source receipts are under each testing worktree's ignored `artifacts/testing` directory. No release tag, immutable public release, candidate registration or native installation has been created. A later release must recheck the current stable versions; these reserved local version numbers are not permission to overwrite a release or downgrade stable.
