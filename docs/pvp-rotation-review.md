## Cross-cutting conclusions

- The final common-action review found an additional omission outside the 21 job files: `Combos/PvP/ALL/ALL.cs` supplies emergency Recuperate, Guard and Quick Purify. New job-scoped engine capabilities delegate these existing branches on Accord rotation inputs (Support for Recuperate; Protection for Guard/Purify). Their saved thresholds/status choices and existing special-state restrictions remain intact. Stock global preset membership is not rewritten; native controls and unmanaged jobs retain their previous behavior.
- Do not blanket-enable every preset or blanket-disable every standalone replacement. Preserve compatible personal policies and native-button preferences.
- Full supported rotation does not imply automatic initiation of every LB: several jobs only implement LB follow-through. Those native controls stay accessible.
- Newly delegated preset families need matching manual selector ownership and explicit exclusion enforcement; changing JSON alone is not sufficient.
- Ninja one-button policy: use the existing area path when multiple eligible enemies are in its relevant area, otherwise ST. Keep that decision stable during an initiated mudra sequence so count changes cannot change the planned mudras mid-sequence. Two-button mode stays explicit. Exact count/range integration and tests are still pending.
- Every scenario in the table is a required verification target, not an assertion that a test already exists or passes.

## Implementation and evidence

The local implementation restores the reviewed delegated presets, adds the common-action capabilities, preserves explicit saved policy values, updates manual selector families, and separates PvP action-route exclusions from PvE. The full-rotation input routes through the selected ST/AoE exclusion policy, rather than combining their exclusions. Ninja uses the existing Goka Mekkyaku target-area enemy count at two or more eligible enemies; its choice stays stable during Three Mudra. The distinct full-rotation input leaves the existing controller ST/AoE inputs explicit.

Automated checks cover all 21 jobs and all 16 category combinations, both button modes and all-manual capacity; actual enabled preset/feature outcomes; Bard retention without changing delegation; scoped exclusion deletion; saved false policy values; overlay precedence, status writes, dirty-editor rebasing and restart; native hotbar simulation/rollback and selected-bar ownership. Existing PvE, gathering, logout and controller regressions remain in the suite. The all-manual default fits two bars for all reviewed profiles.

The source decisions in the table have been implemented. The gameplay scenarios remain an in-game acceptance checklist: no simulated assertion establishes real combat timing, targeting, channel behavior or UI appearance. These have not been tested in a live PvP match here.
