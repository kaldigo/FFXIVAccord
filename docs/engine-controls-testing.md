# Accord-owned engine controls (testing)

Accord owns the automation server-bar entry. Wrath and RSR no longer register clickable server-bar entries in these testing builds. The existing Accord support/protection/burst/class-mechanics entries remain separate permissions. The automation engine selector offers only loaded Accord-compatible Wrath/RSR forks verified through their ownership API, not upstream builds matched by display name. Wrath handles buttons; the single checkbox and lightning A/M entry start or stop the selected automatic engine. Selection is saved and also used for AutoDuty following. Switching an active engine uses the stop/settle/start handoff. Auto rotation is a saved user choice. Reloading temporarily stops execution, then restores the chosen runner after settings and ownership verification.

Before starting, Accord reapplies settings for its selected classes to Wrath through the transaction API. It applies its saved RSR preferences and reads them back before starting RSR. Missing settings, rejected writes, mismatched read-back, a missing selected engine or lost ownership pause execution without clearing the saved choice; Accord retries automatically. RSR settings are applied and verified automatically even while auto rotation is off, on class changes, after preference edits and when the engine becomes available. A two-second check detects drift and retries failures; only differing values are written. No manual engine-apply action is exposed. Auto rotation uses one checkbox. Teaching mode is disabled for automatic execution. Engine replies report actual runner state as well as ownership permission.

Global rotation preferences no longer defer to saved Wrath preferences. Sparse old configurations resolve to Accord defaults: party-combat targeting, range 30, AoE threshold 3, combat only, openers enabled, opener potions and activity untargeted AoE disabled. Role/class overrides inherit from Accord globals. Existing explicit Accord choices remain intact.

Healer rotation settings now contain saved options for healing abilities in damage buttons and separately for healing GCDs. Auto support is required. These select the existing WHM/SCH/AST/SGE healing providers and their target/readiness checks; dedicated healing buttons remain available. Damage buttons still belong to Wrath when RSR owns unattended execution. RSR preferences configure its independent automatic healing behavior, not Wrath's manual button suggestions.

RSR keeps its plugin identity and commands. Its installer icon matches the Accord family; automatic first-start tutorial and update popups are suppressed. Manual tutorial access remains. During Accord ownership, RSR does not acquire a second upstream Wrath control lease.

Native verification: confirm the installed versions and enable diagnostic capture; exercise Wrath and RSR automation versus manual Wrath buttons, both-engine and single-engine installations, stop/start, reload, class changes, support disabled/enabled, ability-only healing and GCD healing. Ownership, settings verification and isolation failures are recorded. Build and mock tests cannot establish that an in-game action was executed successfully.

## Server-bar symbols

Auto rotation uses one native lightning icon (`ElementLightning`) followed by A for active automation or M for manual/button-driven play, matching the other Accord entries. An ellipsis means the handoff is still starting; details and errors remain in the tooltip. Do not replace the icon with a second off-state symbol. The native sprout (`NewAdventurer`) is reserved for future teaching mode; this change does not implement or enable teaching mode.

Learning mode will require the compatible RSR fork regardless of the selected automation engine. Its sprout icon remains reserved; this update does not implement learning mode. A present engine with a missing/broken ownership API is not treated as absent. Engine availability changes pause a running handoff. Accord retries the saved selected engine; it never silently chooses a different engine.

## Persistent rotation improvements

The previous session-only provider switches are retired. Global automation contains saved Wrath rotation improvements and targeting preferences, visible without opening a trace. New and existing Accord configurations default job improvements, BossMod forecast reading, mitigation spacing, ground targeting and PvE/PvP target selection on. Explicit saved choices override defaults. Automatic enemy acquisition/coverage selection is enabled; visible retargeting, focus overrides and applying overrides during automation remain separate saved options. Healing inclusion and GCD healing retain the existing global/role/class Rotation behaviour settings and support permission. Raise/cleanse inclusion remain explicit saved choices.

Accord continuously applies and reads back the full desired configuration through `WrathCombo.RotationSettings.v1`, including during manual play. The engine persists the applied copy and restores it at load before action processing, including a reload during combat. Mutations wait for combat/action preparation to finish; unchanged verification does not reset actions or write configuration. Missing APIs, rejected changes and read-back mismatch are visible and prevent automation using an unverified configuration. Save failure restores the previous runtime and in-memory configuration. Diagnostics record `Settings.WrathSelectionVerified` with the actual effective switch values.

AutoDuty following is now saved. The saved master switch and saved following switch are independent: following gates execution on current navigation, including after reload, without changing either choice. Direct on/off commands only change the master switch. Temporary diagnostic capture retains its explicit start/stop lifetime; it is not a source of gameplay configuration.

Validation includes production engine API save/reload and active feature gates, malformed batch rejection, combat rejection without clearing a commitment, disk-save rollback, Accord preference serialization, batch application, unchanged verification, API drift rejection and restored choices after engine reload. Native combat acceptance is still pending.

## Saved automation choice and lease recovery

The auto-rotation checkbox reflects `AutoRotationEnabled`, not current runner state. Temporary pauses, engine updates, API failures and plugin disposal never clear it. The lightning indicator shows A when running, an ellipsis while enabled but waiting, and M only when explicitly disabled. Accord retries the selected engine every two seconds while enabled and the player is available. AutoDuty-follow pauses execution while navigation is unavailable/stopped; it preserves the master choice and resumes during navigation. Logging status reads are read-only.

Runner-state verification now distinguishes a connected but stopped runner from an engine disconnect. State transitions are also written to the normal Dalamud log, so the initiating failure can be investigated even if detailed capture starts later.

Automation startup recovers an existing settings operation before preparing a fresh one. An unchanged settings patch is acknowledged locally without another engine transaction. Under Accord coordination, Wrath accepts persistent baseline settings transactions even when external runtime leases exist; standalone Wrath retains its original lease protection. Accord's master authority takes precedence over external auto-rotation state leases while coordinated. Old operation recovery preserves the latest independent automation, engine-selection and rotation-preference choices.

Regression coverage executes the production runner enabled expression and settings transaction path with an external lease, including coordinated on/off, standalone behavior and idempotent recovery. Saved on/off survives serialization; paused AutoDuty and missing engines do not change that choice. Builds and regression tests do not establish native combat performance.
